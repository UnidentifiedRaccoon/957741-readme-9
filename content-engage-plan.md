# План для модулей content и engage

## Что уже есть
- В `account-service` модули вынесены в библиотеки: `authentication-module` (controller/service/dto/rdo) и `blog-user-module` (entity/factory/repository + Mongoose schema). Репозитории экспортируются модулем и инжектятся в сервисы. В `AppModule` они подключаются вместе с конфигом и подключением к базе (`AccountConfigModule` + `getMongooseOptions`).
- Общие типы домена описаны в `@project/core` (`Post`, `Tag`, `Like`, `Comment`, `Subscription`, `PostType`, `PostStatus` и т.д.). Общие утилиты маппинга/конфигов — в `@project/helpers` и `@project/data-access`.
- Для content/engage уже есть Prisma-схемы и `PrismaClientModule` в `@project/content-models` и `@project/engage-models`, но бизнес-модулей и репозиториев ещё нет.

## Content-service: что нужно собрать
- **Конфиг**: модуль наподобие `AccountConfigModule` с `ConfigModule.forRoot`, валидацией `PORT`, `DATABASE_URL` и выдачей `PrismaClientModule` (PostgreSQL).
- **Доменные библиотеки** (например, `libs/content/post` и `libs/content/tag`):
  - `PostEntity`, `TagEntity` реализуют интерфейсы `Post`/`Tag`; фабрики `PostFactory`, `TagFactory`.
  - Репозитории на Prisma (расширение/переопределение `BasePostgresRepository`) с методами: CRUD, выборки по пользователю/тегам/типу/статусу, поиск по заголовку, сортировки (дата/лайки/комментарии), пагинация, работа с черновиками, репостами, массовое получение постов по списку userId (для ленты).
  - Модуль подключает `PrismaClientModule` и экспортирует репозитории.
- **Прикладные сервисы и контроллеры**:
  - `PostService` с операциями создания по типам (video/text/quote/photo/link), обновления/удаления (с проверкой владельца), публикации/драфта, репоста, получения детальной карточки, списка, черновиков, поиска, тегированной выборки. При удалении поста — вызов в engage для чистки комментариев/лайков (HTTP или событие).
  - `TagService` для создания/нормализации тегов и выборок по тегам.
  - DTO для команд/квери (отдельные DTO под типы постов, фильтры/сортировки/пагинацию), RDO для выдачи поста/списка с подсчётами (лайки/комментарии/автор заполняется на API Gateway).
  - Swagger-аннотации и валидация (`class-validator`) по требованиям ТЗ.
- **Интеграции**: методы для API Gateway — агрегированные ответы, возможность передавать `userIds` (для ленты по подпискам), поиск по title, сервис выдачи только опубликованных постов.

## Engage-service: что нужно собрать
- **Конфиг**: аналогичный модуль для PostgreSQL + `PrismaClientModule` из `@project/engage-models`.
- **Доменные библиотеки** (например, `libs/engage/comment`, `libs/engage/like`, `libs/engage/subscription`):
  - `LikeEntity`, `CommentEntity`, `SubscriptionEntity` + фабрики; репозитории на Prisma с методами: поставить/снять лайк, посчитать лайки по посту, создать/удалить комментарий, отдать комментарии по посту с пагинацией, оформить/отменить подписку, получить списки подписок/подписчиков.
  - Экспорт репозиториев через Nest-модули для переиспользования в контроллерах и, при необходимости, в API Gateway.
- **Прикладные сервисы и контроллеры**:
  - `LikeController`/`Service`: лайк/анлайк, получение количества лайков по посту.
  - `CommentController`/`Service`: создание, удаление только владельцем, получение комментариев по посту (50 по умолчанию, постранично).
  - `SubscriptionController`/`Service`: подписка/отписка, получение списка id авторов для формирования ленты, подсчёт подписчиков пользователя.
  - DTO/RDO + Swagger и валидация входных данных.
- **Интеграции**: эндпоинты/события для очистки данных при удалении поста (массовое удаление лайков/комментариев), отдача статистики для сортировки постов по популярности/комментам.

## Итеративный порядок работ
1. Завести конфиг-библиотеки для content и engage (application + postgres) и подключить их в `content-service` и `engage-service`.
2. Доработать `BasePostgresRepository` или реализовать конкретные Prisma-репозитории с полной CRUD-логикой и маппингом Entity ↔ Prisma-DTO.
3. Собрать доменные модули (entity/factory/repository/module) для Post/Tag, Comment/Like/Subscription, подключить `PrismaClientModule`.
4. Реализовать сервисы и контроллеры с DTO/RDO и валидацией под требования ТЗ (создание/редактирование постов, репосты, списки с сортировкой/пагинацией, комментарии, лайки, подписки).
5. Добавить взаимодействие content ↔ engage при удалении поста и для получения статистик, задокументировать Swagger-спеки в сервисах.
6. Обновить `AppModule` в приложениях, подготовить `.http`-файлы/песочницу для ручной проверки, наметить автотесты для критичных сценариев (CRUD постов, лайк/коммент, подписка).
