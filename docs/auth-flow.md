## Guards, Pipes, Interceptors, Filters

### Порядок выполнения в NestJS

```
                        ВХОДЯЩИЙ ЗАПРОС
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      1. MIDDLEWARE                              │
│  Выполняется до Guards. Может модифицировать request/response  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                        2. GUARDS                                │
│  Определяют, будет ли запрос обработан                         │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ CheckAuthGuard (API Gateway)                            │   │
│  │ - Проверяет токен через account-service                 │   │
│  │ - Добавляет user в request                              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ LocalAuthGuard (Account-Service, login)                 │   │
│  │ - Использует LocalStrategy                              │   │
│  │ - Проверяет email/password                              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ JwtAuthGuard (Account-Service)                          │   │
│  │ - Использует JwtAccessStrategy                          │   │
│  │ - Проверяет и декодирует access token                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ JwtRefreshGuard (Account-Service, refresh)              │   │
│  │ - Использует JwtRefreshStrategy                         │   │
│  │ - Проверяет refresh token и сессию в БД                 │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  return true  → продолжить                                      │
│  return false → 403 Forbidden                                   │
│  throw        → соответствующая ошибка                         │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     3. INTERCEPTORS (before)                    │
│  Выполняется ДО контроллера                                    │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ InjectUserIdInterceptor                                 │   │
│  │ - Добавляет userId из токена в body запроса             │   │
│  │ - request.body.userId = request.user.sub                │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ RequestIdInterceptor                                    │   │
│  │ - Генерирует уникальный ID запроса                      │   │
│  │ - Добавляет X-Request-Id в headers                      │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                         4. PIPES                                │
│  Трансформация и валидация данных                              │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ ValidationPipe (глобальный)                             │   │
│  │ - Использует class-validator                            │   │
│  │ - Валидирует DTO                                        │   │
│  │ - Преобразует типы                                      │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ MongoIdValidationPipe                                   │   │
│  │ - Проверяет валидность MongoDB ObjectId                 │   │
│  │ - Используется для параметров :id                       │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      5. CONTROLLER                              │
│  Обработка запроса и вызов сервисов                            │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    6. INTERCEPTORS (after)                      │
│  Выполняется ПОСЛЕ контроллера                                 │
│  Может трансформировать ответ                                  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    7. EXCEPTION FILTERS                         │
│  Обработка ошибок на любом этапе                               │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ AxiosExceptionFilter (API Gateway)                      │   │
│  │ - Обрабатывает ошибки от внутренних сервисов            │   │
│  │ - Преобразует AxiosError в HTTP response                │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
                       ИСХОДЯЩИЙ ОТВЕТ
```

### Пример использования в контроллере

```typescript
@ApiTags('blog')
@Controller('blog')
@UseFilters(AxiosExceptionFilter)        // 7. Exception Filter
export class ContentController {
  
  @UseGuards(CheckAuthGuard)             // 2. Guard
  @UseInterceptors(InjectUserIdInterceptor) // 3. Interceptor
  @Post()
  public async create(
    @Body() dto: CreatePostDto           // 4. Pipes (ValidationPipe)
  ) {
    // 5. Controller logic
  }

  @Get(':id')
  public async getOne(
    @Param('id', MongoIdValidationPipe) id: string  // 4. Custom Pipe
  ) {
    // 5. Controller logic
  }
}
```

## Стратегии аутентификации

### LocalStrategy (для login)

```
┌─────────────────────────────────────────────────────────────────┐
│                        LocalStrategy                            │
├─────────────────────────────────────────────────────────────────┤
│  extends PassportStrategy(Strategy)                             │
│                                                                 │
│  Конфигурация:                                                  │
│  - usernameField: 'email'                                       │
│                                                                 │
│  validate(email, password):                                     │
│    1. Вызывает authService.login({email, password})             │
│    2. AuthService:                                              │
│       - Ищет пользователя по email                              │
│       - Сравнивает пароль через bcrypt.compare()                │
│       - Возвращает User или бросает исключение                  │
│    3. Passport добавляет User в request.user                    │
└─────────────────────────────────────────────────────────────────┘
```

### JwtAccessStrategy (для protected routes)

```
┌─────────────────────────────────────────────────────────────────┐
│                      JwtAccessStrategy                          │
├─────────────────────────────────────────────────────────────────┤
│  extends PassportStrategy(Strategy)                             │
│                                                                 │
│  Конфигурация:                                                  │
│  - jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken()     │
│  - ignoreExpiration: false                                      │
│  - secretOrKey: JWT_ACCESS_TOKEN_SECRET                         │
│                                                                 │
│  validate(payload: TokenPayload):                               │
│    1. JWT уже проверен Passport (подпись + срок действия)       │
│    2. Возвращает payload как есть                               │
│    3. Passport добавляет payload в request.user                 │
└─────────────────────────────────────────────────────────────────┘
```

### JwtRefreshStrategy (для refresh token)

```
┌─────────────────────────────────────────────────────────────────┐
│                      JwtRefreshStrategy                         │
├─────────────────────────────────────────────────────────────────┤
│  extends PassportStrategy(Strategy, 'jwt-refresh')              │
│                                                                 │
│  Конфигурация:                                                  │
│  - jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken()     │
│  - secretOrKey: JWT_REFRESH_TOKEN_SECRET                        │
│                                                                 │
│  validate(payload: RefreshTokenPayload):                        │
│    1. Проверяет существование tokenId в БД                      │
│    2. Удаляет текущую refresh сессию (одноразовый токен)        │
│    3. Удаляет истекшие сессии                                   │
│    4. Получает пользователя по email                            │
│    5. Возвращает User для генерации новых токенов               │
└─────────────────────────────────────────────────────────────────┘
```
